# Parked readiness and automatic profile selection — 22 October 2026

**Superseded readiness policy:** beta 0.8.0-beta.3 delegates physical service-readiness to GSX and removes live engine/brake polling, including the Fenix mapping. The earlier implementation/evidence below remains historical. See [current policy](gsx-readiness-policy.md).

A read-only live probe of the current Fenix A319 found on-ground true, stationary ground speed and engines off, but the standard BRAKE PARKING POSITION SimVar returned zero while the cockpit brake was set. That is a real mismatch; relaxing the safe-parking guard would hide it.

ADM now reads the Fenix A319/A320/A321 cockpit variable `L:S_MIP_PARKING_BRAKE` through a separate read-only SimConnect definition when the observed aircraft title identifies that family. The mapping is documented in the integration author's [Fenix native profile](https://raw.githubusercontent.com/Fragtality/Any2GSX-Plugins/master/FenixProfile/FNX.Native.json). [Microsoft documents read access to L variables through SimConnect](https://docs.flightsimulator.com/msfs2024/retail/programming-apis/simconnect/api-reference/events-and-data/simconnect_addtodatadefinition/). No L variable or simulator control is written. A missing/stale/unrecognised Fenix value remains unknown, not a fallback that declares the brake set. Other aircraft keep the standard reading. Fenix state is cleared on aircraft change.

The updated eight-second live probe observed cockpit value 1 and **parking brake true, engines false, on ground true**, with a matching A319 GSX plan. Evidence: `[private local integration capture]`. Both probes were read-only: attempted=false, accepted=false, no service requests. This verifies the current brake reading, not a complete handling cycle or every Fenix variant/version.

SDK booleans now accept finite nonzero values, including -1, as true, following the [official request-data contract](https://docs.flightsimulator.com/msfs2024/flighting/programming-apis/simconnect/api-reference/events-and-data/simconnect_requestdataonsimobject/). Nonfinite data stays unknown. Preparation now identifies the actual missing/released brake or engine reading instead of always repeating a generic parked instruction. Readiness diagnostics are logged on state changes, not every poll.

The 25 supplied profiles are validated bundled defaults and are registered as explicit local airline designators at startup. A validated imported airline callsign resolves its profile; registrations/two-letter commercial numbers still do not invent an ICAO airline. Profiles now selects that airline, aircraft and operation once per changed flight context. Repeated loadsheet/plan-figure updates preserve the pilot's profile draft. Flight displays the resolved profile; saving does not rewrite an active session plan. User JSON overrides bundled defaults, so updating the addon does not erase customisation.
